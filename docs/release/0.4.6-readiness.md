## 本轮新发现并修复

1. **云端账单跨设备/跨订单误匹配**：原版 `data/SettlementEngine.kt::matchBill` 和 iOS `CloudShowerController.settle` 的时间回退过宽，可能采纳别的设备账单或之后的新订单。提取 Foundation-only `SettlementBillMatcher`，仍优先 orderNo，再兼容缺失 orderNo 时的 orderId；拒绝重复行和设备冲突。时间回退必须有本地订单号、同设备 SN、唯一候选、三分钟前至本次关闭的范围，不凭时间猜测无本地编号的历史单。
2. **失败/矛盾响应带金额也被采纳**：直接结算查询现在要求 success，并拒绝返回的设备或订单标识与当前单矛盾；账单列表也要求 success。Decimal 单独解析还会接受 `40pending` 的数字前缀，现补充完整有限数值检查。未知状态保留 pending，不增加上传或扣费请求。
3. **云端跨月恢复漏查**：旧回退仅查当前月；现在先查原订单开始月份，再兼容当前月，保留原有三轮及等待语义。这是只读 GET 的正确月份修复。标准日期按校园服务的 Asia/Shanghai 解析。
4. **小组件主体误操作**：Android `widget/WidgetRenderer.kt` 的 widget_root 打开 App；iOS 以前整个主体关联 start/stop。改为只读 show，只有明确的“开始/结束”Link 保持控制功能。LiveContainer 不嵌入 Widget；此项还需普通签名版实装验证。
5. **嵌入扩展版本落后**：Widget 仍为 0.3.0（3），和主 App 不一致；现两者统一 0.4.6（10）。名称「淋浴」、图标、Bundle Identifier、iOS 16 部署目标保留。
6. **应用信息缺少自身版本与下载入口**：原 UI 只展示 Android 参考版本。补充 Bundle 中的实际 iOS 版本和 iOS Releases 链接，保留且明确区分原版更新列表。不会把 APK 当作 iOS 更新安装。

以上没有更换服务接口、签名算法、设备指令或结算上传/写回顺序。对原版时间猜测路径的收紧属于避免错归账的安全差异；不能称为逐字照抄。

## 发布闸门与一次构建额度

1. Ubuntu 只读/Mock 预检必须先通过：固定 SHA、资源与版本、POSIX 打包、51 项交易核心。`preflight_only=true` 不分配 Mac、不构建 IPA。
2. 同一固定 SHA 才能请求唯一一次正式 IPA 构建；并发组不取消/替换已运行任务，不并发启动多个构建。
3. 正式工作流再次预检，在 Mac 执行核心和全量 iOS/UI 测试；测试失败即不进入真机 build，不使用 continue-on-error 或跳过测试。
4. 成功后验证 device arm64、codesign --verify --deep --strict、包结构、CRC、成员哈希及来源 SHA。下载复核后才发布测试版 Release，复用同一个 IPA。
5. 若正式工作流失败，停止，不自动 rerun/重新 dispatch；可以修源码并报告，但新增构建必须另行授权。
6. 不满足安全审查或测试闸门时不出包。成功后也只称“测试版”；本任务结束恢复禁止自动打包的默认规则。

## 必要平台差异与未完成实机项

- Core Bluetooth 无扫描 MAC，只能 UUID 选择连接后读设备自报身份；弱信号、设备忙/正在交易时自动命名会延期，绝不自动开关阀或结算。
- iOS 没有 Android 前台服务的无限后台执行保证；后台挂起、杀进程期间不能保证 HTTP/BLE 持续执行。持久未知/未结算单须回到前台核实，不能宣称后台一直可靠清账。
- LiveContainer IPA 不含 Widget 扩展，不能独立安装为 Apple 分发签名应用；通知能力及 Keychain/后台/蓝牙授权仍依赖宿主。普通签名、App Group 与 Widget 仍需另外验证。
- 圆形动画、状态栏/Home Indicator、背景 GPU、内存、iPad 分屏及不同屏幕/折叠形态待真机；没有 FPS 或内存测量值，不声称零掉帧/零 Bug。
- 必须在原手机保留应用数据升级，分别验证旧订单账单、设备关阀证据、采集及写回。自动化不操作真实水表，也不证明校园服务器当前性能与固件兼容。
- 背景恢复默认重置三参数、SHOWER 独立强调色按用户要求实现，属于对 Android 原版行为的明确扩展。详见背景专项报告。
